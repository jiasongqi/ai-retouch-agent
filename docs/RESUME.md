# 简历写法

把这个项目写成「能上架的 Agent 工作台」，不要写成「调了一次文生图 API」。

## 一句话

面向电商商品图的 AI Agent 工作台：自然语言规划修图步骤，统一工具注册表驱动抠图 / 换背景 / 图层 / 多平台导出，SSE 实时更新画布。

## 项目信息

- 名称：AI 修图智能体（ai-retouch-agent）
- 技术：Python 3.13 · FastAPI · LangGraph · React 19 · react-konva · ARQ · Redis · PostgreSQL · MinIO
- 仓库：https://github.com/jiasongqi/ai-retouch-agent

## 职责可以这样写

- 设计并实现 LangGraph 规划器：模型只产出 JSON 计划，服务端做工具存在性、参数、依赖与环检测后再执行。
- 维护统一 ToolRegistry（26 个工具），UI 按钮与 Agent 共用同一份规格，避免两套接口漂移。
- 用 ARQ + Redis Pub/Sub + SSE 推送多步修图进度；画布用 react-konva 维护图层文档、撤销重做与前后对比。
- 落地可上架能力：接触阴影 / 倒影、淘宝·亚马逊·抖音画幅、12 场景库、Brand Kit、一键套图。
- 提供 mock Provider，本地零 Key 跑通；生产切 DashScope。Docker 多阶段构建，前端打进后端镜像同源托管。

按你真实做过的条目删减，没做的不要写。

## STAR 示例

**S**：电商主图要白底、场景、竖版各一张，聊天式出图对不齐平台规范，也无法局部重做。  
**T**：做成可确认计划的 Agent 工作台，同一次会话里完成精修和多画幅交付。  
**A**：计划与执行解耦；工具一处注册；平台导出按安全区和主体占比放置，而不是裁切。  
**R**：mock 下可演示全流程；接模型后同一条链路出可上架物料。量化结果用你自己的评测或演示数据。

## 个人贡献（示例）

只写你合进仓库的改动，例如：

- 影棚精修：接触阴影 + 倒影，写成可复用工具而不是提示词碰运气。
- 平台画幅：按淘宝 / 亚马逊 / 抖音规范放置主体，避免「主体占比过小」。
- 场景库与 Brand Kit：固定场景本地合成，主色 / 安全边距 / 角标套到导出。
- 一键套图：白底 + 场景 + 卖点 + 9:16 一次出齐。
- 落地页与 Playwright：修前修后、Demo GIF、主路径回归。

## 不要这样写

- 「熟悉 ChatGPT / 调用了通义万相」——看不出系统设计。
- 「使用了 FastAPI、React」——没有难点。
- 把别人的项目写成自己独立完成的产品。
- 简历里贴 API Key、数据库连接串、内网地址。

## 面试官可能追问的一句话

「为什么不让模型直接调工具？」  
因为执行前必须校验工具名、参数和依赖，且用户要能确认、单步重试或取消。规划错了可以改计划，不必把错误像素写进画布。展开见 [面试题解](INTERVIEW.md)。
